# 20. Accessibility

Follow modern accessibility practices.

Use:

* Semantic HTML
* Proper heading hierarchy
* Accessible buttons
* Accessible links
* Alt text for meaningful images
* Keyboard navigation
* Adequate contrast
* Visible focus states
* Appropriate form labels

Do not sacrifice accessibility for visual effects.

---

# 21. Performance

Performance is a priority.

When implementing the website:

* Optimize images
* Avoid unnecessary JavaScript
* Lazy-load appropriate assets
* Avoid excessive animation libraries
* Avoid unnecessarily large dependencies
* Minimize layout shifts
* Optimize fonts
* Use modern image formats where appropriate
* Keep mobile performance in mind

Do not add a dependency when native browser functionality or an existing project dependency is sufficient.

---

# 23. Development Principles

When working on the website:

1. Inspect the existing codebase before making changes.
2. Understand the existing architecture.
3. Reuse existing components when appropriate.
4. Avoid unnecessary rewrites.
5. Keep components maintainable.
6. Keep naming consistent.
7. Keep styling consistent.
8. Do not introduce duplicate implementations.
9. Do not remove working functionality without a reason.
10. Test changes before considering a task complete.
11. Check desktop and mobile behavior.
12. Check console errors.
13. Check broken links and missing assets.
14. Keep the code production-ready.

---

# 24. Before Making Major Changes

For significant changes:

* Explain the intended approach.
* Identify affected files.
* Check existing components first.
* Check whether the requested functionality already exists.
* Avoid duplicating existing systems.

For small obvious changes, do not overcomplicate the process.

# 33. Final Development Standard

Every implementation should aim to satisfy four dimensions:

### Brand

Does this feel like Glitci?

### UX

Is this intuitive and easy to use?

### Technology

Is this clean, performant, responsive, and maintainable?

### Business

Does this help Glitci communicate its value and generate opportunities?

A technically impressive website that does not communicate Glitci clearly is not considered successful.

A beautiful website that performs poorly is also not considered successful.

The target is:

**Beautiful + Fast + Functional + Clear + Business-Focused**
